# RC 50,000 根回测分段测量

2026-11-25 在 Linux 6.18.57、Xeon Platinum 8573C、Node 24.19.0、Chromium 154.0.8037.57 实测。容器可见 5 个逻辑 CPU，配额为 4 CPU / 16 GiB；共享主机的调度与 GC 会造成波动。每次创建全新浏览器页面、Worker 和三条完整曲线。样本是固定 50,000 根合成分钟线、MA 2/4、1,000 USDT、费用及双侧滑点各 10 bps。两个版本均成交 8,331 笔、产生 50,001 个权益点。

## 同程序前后对照

将本次诊断脚本和 tests/performance 复制到原始 e27a728 工作树测量基线；两侧各 3 次，结果按毫秒取整。更换版本或机器后可运行 `node scripts/profile-backtest.mjs`。默认采用 Playwright Chromium；使用系统 Chromium 时设 `PLAYWRIGHT_CHROMIUM_EXECUTABLE`，Windows Chrome/Edge 分别设 `E2E_BROWSER=chrome` / `msedge`。程序在 work 内临时构建，以随机回环端口启动，不写浏览器数据库。CI 与本地可通过日志的 RC_PROFILE 读取每次采样，原始本地数据见 [rc-performance-samples.json](rc-performance-samples.json)。

## 瓶颈、试验与内存

50k 的完整 payload Hash 和大型对象传输比策略信号本身耗时更高。基线初次压力抽样 3 次时，耗时最久的一次总计 6,530ms，其中封存 2,642ms、输出交付 1,262ms、主线程间隔 1,052ms，超出 1000ms 门槛。完整 UI 基线另出现保存数据/检查 CSV 的前置超时；终止后剩余重复次数未计为通过。历史 5B 已另存 2C 和规则回测成功提示等待 5 秒的失败证据。[历史日志](phase-5b-evidence/check-initial-failure.log)

RC 保持原规范键排序、UTF-16 转义及 SHA-256，按约 64 KiB 累积 ASCII 串。无需转义的可打印 ASCII 金额、键和枚举可以直接写入，减少逐 token 数组分配。当前 Chrome 下封存中位耗时从 1,259 降至 928ms。整段中位缩短，但这组 3 次的整段最大值略有上升；调度环境无法保证每次运行在 5 秒内。另一组探索性 RC 采样 5 次，中位 / 最大 3,738 / 5,162ms（含绘图），主线程最大 662ms。上述 Hash 优化未改动成交、统计或绘图精度。

曾尝试重建按键排序的对象再调用原生 JSON 序列化，3 次中封存中位 1,554ms，最慢 7,342ms。另一次尝试将整个返回对象 JSON 序列化并在主线程解析，交付中位 1,534ms、最慢 2,338ms，主线程最大间隔 1,319ms。两种尝试均已撤回。浏览器端导出改为单一 Blob，省去此前随下载文本重复回传的完整实验。

同程序 RC 结果交付后主线程使用的 JS 堆采样最大约 45.2 MiB，绘图后约 115.6 MiB。这两个时点均不含 Worker 堆、浏览器进程总 RSS、原生图表及两点间峰值。原生 SHA-256 仍需要完整规范字节缓冲；全量报告、结构化克隆和绘图在内存紧张的浏览器中仍有成本。作用域维持 50,000 根上限，并保留全点展示及完整报告。

## 正确性和取消

固定合成输入在基线及 RC 全部六次产生相同 runHash 和覆盖策略、数据、逐笔成交、逐点权益与全部统计的 payloadHash，两者均有脚本断言。额外用原规范文本和 Node SHA-256 对照所有 ASCII 字节、控制字符、数字形键、长串跨块、非 ASCII 和孤立代理字符。Windows 三份 BTC 实验另行复核，此合成场景只用于性能和确定性测量。

回测 Worker 在完成、错误、反序列化失败、显式取消时终止；工作台以任务代次屏蔽过期回应。组合测试覆盖取消后模拟旧 Worker 仍投递成功、Worker error/messageerror、无数据写入及后续恢复重试。[Worker 回归](../tests/integration/experiment-worker.test.ts)

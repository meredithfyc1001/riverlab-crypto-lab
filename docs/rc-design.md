# V1.0 RC 设计与验收依据

基线为 PR #10 的合并提交 `e27a728ac53dc7a3f6ad73fbcbd298f4527ccb54`，候选版本为 `1.0.0-rc.1`。目标是让现有用户能带着原数据、原策略或完整实验报告验证升级后的结果，让首次使用者从明确选择的样本完成一次回测。八个页面沿用本机 HTTP 与原 hash 路由，继续使用单币种、现货多头、虚拟资金模型。

## 可复现的数据边界

复用原数据与质量契约、收盘信号到下一根开盘的时序、18 位定点资金、费用、滑点、止盈止损和原版本标识。显示用的数值转换只发生在绘图边界。性能变更必须用原 Windows 实验逐笔成交、逐点曲线、统计及 runHash 验证，并通过原独立数值参考。原始实验记录只在核查字段和隐私后用作回归输入。[历史基准](v1-rc-windows-baseline.md)

实验导入由用户选取单个本地文件。先限制字节数，Worker 检查格式和版本，校验 payloadHash，再用内嵌数据、参数与策略快照重新运行并比较完整结果。只在校验成功后预览。确认时以事务向实验和摘要库同时新增，冲突或事务中止均不得留下部分记录。每次导入独立于原策略库和数据集库。其他对象继续使用各自的导入入口及依赖关系。[备份范围](rc-backup.md)

## 性能与交互

对 50,000 根输入分段观测策略、成交账本、统计、Hash、Worker 传输和全点曲线绘制；记录重复测量、资源配置、观察方法和测量边界。保留原业务断言、20 秒整体门槛及 1000ms 主线程观察间隔。取消、异常退出、迟到消息及大对象生命周期列入复核。页面拆包须兼容首次直达任一路由和离线本地资源加载。

空库展示内置历史样本和人工合成样本的独立入口。导入、质量检查、主动保存和回测构成一条可验证流程。保持旧数据不受首次引导影响。每页保留风险提示，键盘可操作，窄屏可读；存储失败和验证失败需有明确反馈。

## 交付条件

- 对锁文件执行全树和生产依赖审计，按可达范围区分开发工具和产品依赖，优先兼容升级。
- 运行全量 check 和独立 Python 参考，并在 Ubuntu Chromium、Windows Chrome、Windows Edge 核实对应 head 的实际日志。
- Windows 在中文空格路径解压真实 ZIP，分别以 Chrome、Edge 验证 BAT 前台回环服务、已有功能、实验文件恢复和停止释放端口。三组质量通过后验证 ZIP，验证成功后上传 14 天制品。
- 在 Draft PR 交付说明记录完整 SHA、内层 ZIP 摘要、可访问链接、实际有效期与待测项目。候选进入本地验收后，由用户决定后续处置。物理断网继续记为 NOT TESTED。

## 报告库修复专项

从 Phase 5E Draft PR 的交付说明核对联合包提交和内层 ZIP SHA-256，使用独立临时浏览器配置。验完两浏览器后记录各库实际可用摘要和隔离数，以及健康报告的原始与重导 Hash。正式保存资料可在原配置中继续使用。故障注入仅在可丢弃的测试副本执行。

1. 经界面导入并保存 RC 单币实验和两份共享组合实验，运行并保存多份不同名研究报告，先导出参考 JSON。
2. 在包内 acceptance 文件夹找到 acceptance-library-fixture.js。打开本机应用的 DevTools → Sources → Snippets，新建临时片段，复制文件内容并运行。Console 执行 `await riverlabAcceptanceFixtures('5D')`。核对返回的来源和新增主键，刷新页面。该夹具向共享实验与市场状态库各追加一条坏摘要，并创建一份可通过列表选中的坏正文副本。
3. 核对两处提示中的库名、可用摘要数与各 1 条隔离数。两条坏摘要不可选择。同库的健康来源和其他库的单币实验可运行。健康报告可分别重开、重新计算、导出 JSON 与 CSV。核对原 Hash 与 JSON 文件字节。
4. 打开“联合验收 · 正文损坏”的报告，记录明确的校验错误，再重开健康报告。回看存储中的故障样本仍在原位置。用浏览器的拒绝存储环境复查时应见读取失败，加载失败的库不应显示空库结论。自动化另覆盖实际读事务中止。

# Phase 5C-B Windows 本机验收清单

适用版本 `1.1.0-test.2`。从 [Draft PR #13](https://github.com/meredithfyc1001/riverlab-crypto-lab/pull/13) 取最终 clean head 的制品、到期时间和内层 ZIP SHA-256。在 Chrome 和 Edge 各记录浏览器版本、操作、观察值及 PASS、FAIL、BLOCKED 或 NOT TESTED。此次用户实机验收待执行。5C-A 用户实际结果见[基线报告](phase-5c-b-windows-baseline.md)。

| 项目         | 操作与预期                                                                                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 验包         | 用 PowerShell `Get-FileHash -Algorithm SHA256` 核对下载制品中的内层 ZIP；解压至中文与空格路径，核对 build-info、完整提交、版本及逐文件清单。                                                     |
| 启停         | 使用 Node.js 24 LTS，从 BAT 启动本机回环服务。记录 HTTP 地址及端口。测试结束在控制台输入 q 和回车后确认端口释放。                                                                                |
| 固定子账户   | 从组合入口打开 5C-A 的双资产、五资产原件；对照旧报告的完整 Hash、11/18 笔成交与终值。原单币种实验入口分别重算 RC 的 MA 2/4、规则 V1 和规则 V2。                                                  |
| 策略共享现金 | 测两资产及五资产，在同一收盘触发多个策略。分别用内置策略和已保存规则修订，改变显示顺序。按规范交易对核对申请、批准、实际支出、手续费和共享现金。改变现金储备或最小额后核对拒单、余款和资产贡献。 |
| 时序与保护   | 同时出现开盘卖出和另一币买入时，按账本核对可用净款。检查跳空保护优先、同根止盈止损保守选择和根内退出资金可用时点。末根后成交数应为零。                                                           |
| 定期调仓     | 设置两币目标 40%、40% 及现金 20%，周期 N=2。首开盘保持空仓；首笔只能出现在第 3 根开盘。核对部分减仓、加仓及费用使调仓后目标仍有偏差的情况。                                                      |
| 统计         | 以同一收盘估值核对共享现金加持仓市值、组合净盈亏等于各资产贡献之和。比较含成本买入持有曲线、权益曲线和最大回撤，检查调仓前后现金与资产权重。                                                     |
| 保存与恢复   | 两种新模式各保存、刷新重开、完整重算、导出 JSON/CSV。在全新浏览器配置仅用 JSON 恢复，核对原 Hash、订单、费用、全部权益点，再确认保存。                                                           |
| 拒绝与取消   | 试验损坏 JSON、不支持的版本、修改输入或结果、重复 ID、存储失败或取消计算。核对原保存记录仍可打开，页面能再次运行。                                                                               |
| 容量与响应   | 分别运行 2×5,000、5×2,000 根，高频调仓及同时信号。记录运行、导出、恢复和响应耗时。含选区外超过 10,000 根及报告超过 32 MiB 时须明确拒绝。                                                         |
| 物理断网     | **NOT TESTED**。只有实际断开网络后执行刷新、Worker 加载、回测、恢复和导出，才能登记该项结果。                                                                                                    |

# Phase 2A：确定性成交内核与虚拟账本

本轮先审查设计再实现。结论：事件与执行分离、严格阻断坏数据、固定点账本适合当前单币种现货范围；不把 K 线开盘报价当成真实成交。正式策略、止盈止损、收益面板及 M2 完整验收延后。

## 输入、边界与事件顺序

公开入口 `src/core/backtests/index.ts`。`runBacktest` 接收 dataset-v1、`completedThroughUtcMs`、固定信号和配置。核心仅同步纯计算，无 React、DOM、IndexedDB、系统时钟、随机数或网络；SHA-256 使用固定版本 @noble/hashes 的纯计算函数。

重新执行 Phase 1 `assertDataset`，要求完整记录、警告已确认、有效身份与质量快照。再逐根要求严格等周期（任何缺口阻断），每根 `openTime + interval <= completedThroughUtcMs`，不能通过删除未完成根/坏行静默截取。该截止时间由调用者声明，不认证外部数据是否已最终定稿。来源类型/原文件哈希/质量警告保留；文件首尾覆盖与真实性仍未知。空数据、无效 OHLCV、时间重复/倒序/非网格、非安全整数均报错。成交量（包括零量）是合法历史数据；执行时完全忽略，不能用当根尚未完成的整根成交量决定开盘成交。

Phase 1 的 Number 价格只通过 `String(number)` 最短十进制表示转换（包括科学计数），不先做 Number 金额乘加。这精确表示规范字符串，**不能恢复已在 CSV 解析时丢失的原十进制位数**。所有 OHLC 必须可在 18 位小数内精确表示且小于 10^30，否则阻断；不悄悄舍入价格或放宽 Phase 1 规则。

固定 `Signal` 是测试输入：根索引、buy/sell/hold、数量（精确字符串或 all）、原因；每根最多一条，不重排信号，不合并。信号序列必须严格递增且在范围内。禁止将这些预先编写的测试信号宣称为因果策略；核心无法鉴别外部信号作者是否偷看未来。2B 必须另建只暴露历史前缀的策略接口，并验证策略因果性；本轮没有任意回调或正式策略。

每根严格按：① 下一根开盘执行上一收盘的 `OrderIntent`；② 按当根收盘估值快照；③ 在当根完成时间记录信号并生成下一根开盘意图。成交只读取该根 open，不读取 high/low/close/volume 选择价格、方向或成交状态。hold 仅记录信号，无订单。末根 buy/sell 记录 expired / no-next-candle，不产生虚构成交、费用或平仓。

## 成交模型

仅一个输入币种、报价为虚拟 USDT、零初始持仓、现货多头、无杠杆。默认本金1000、手续费10bps、买/卖滑点各10bps、数量8位、最小名义金额0。bps 为0–9999整数，数量精度0–18；禁止未知配置键。买滑点上调开盘价，卖滑点下调；跳空按下一实际开盘处理。限价、盘口深度、成交排队、部分成交、市场冲击、真实交易所过滤器和撮合均不存在。假定所需数量可一次全部成交，完全忽略 volume（包括零量），避免用开盘时尚未知的整根成交量作决定；这是流动性可能被高估的模型假设，输出必须携带。滑点价可超出当根高低范围，不用未来极值裁剪。

指定数量按数量精度向下取整；零数量、低于最小名义金额、卖出超持仓、买入含费超现金均拒单，绝不自动部分成交。all 买入通过整数二分求含费且可承受的最大数量单位；all 卖出当前全部持仓。拒单不改资金。没有初始持仓、借币、负现金或负持仓。

## 精度、舍入与对账

所有金额/价格/数量均内部 BigInt，尺度 S=10^18；输入非负十进制/科学计数字符串，最多128字符，原值小于10^30。对外输出规范十进制字符串（去尾零，零为0），没有 BigInt JSON 或 Number 资金。价格/初始本金/最小名义额/指定数量均要求不损失18位精度；数量额外按配置向下对齐。内部派生数量可超过输入上限；派生现金、数量、市值、权益均必须非负且小于10^78，以限制重复极端价格往返的资源增长。越界阻断整个运行，不返回部分结果或裁剪数量；这不是交易所风控规则。

对非负整数：floor(a/b)=整数除法；ceil(a/b)=(a+b−1)/b。

- 买价 `ceil(open × (10000+buyBps)/10000)`；卖价 `floor(open × (10000−sellBps)/10000)`（单位均为1e−18）。卖价降至0拒单。
- 买名义额 `ceil(price × qty/S)`，卖名义额 `floor(price × qty/S)`；零名义额拒单。
- 双边手续费均为报价币，`ceil(notional × feeBps/10000)`，按已经舍入的名义额计算；不从基础币扣费，不把滑点重复记为费用。可能存在1e−18量级舍入成本，明确接受。
- 买现金减名义额和费、基础币加数量；卖现金加名义额减费、基础币减数量。
- 估值 `marketValue=floor(qty × markPrice/S)`，`equity=cash+marketValue`。逐笔 before/after 均按同一实际开盘价估值（不含滑点），变化包含费用、滑点和舍入；每根及最终按收盘价估值。未平仓按账面市值，未扣假想清仓费用。

每笔保存序号/意图ID/原因/UTC时间/开盘参考价/成交价/数量/名义额/费、before/after现金/仓位/市值/权益、各变化、累计买卖金额/数量/手续费。成交后独立从累计总数检查：`cash=initial−buyQuote+sellQuote−fees`、`position=buyQty−sellQty`、`equity=cash+marketValue` 且非负。公开 `assertLedger` 可对输出重新对账，拒绝链断裂、篡改或不一致。无成本基础/已实现盈亏或收益率统计，2C再定义。

## 可复现身份

规范 JSON：对象键按字典排序；非 ASCII UTF-16 单元转为 JSON unicode escape；数组保持顺序。规范数据 tape 包含 symbol、周期和每根 UTC/OHLC十进制/volume规范字符串；计算实际 SHA-256 `dataHash`，与原CSV `sourceFileSha256` 分开。`signalHash` 绑定数量、索引、原因。`runHash` 绑定数据/信号哈希、算法版本、转换版本、规范化配置及截止时间。

结果 manifest 保存以上身份、数据范围/来源/质量、版本、全部配置/固定信号、初始虚拟本金、运行假设。没有内部 Date.now/UUID/随机种子。需要运行时间时由外部包装记录，不能让墙钟改变计算结果；本轮无实验持久化。相同输入整体 JSON 必须逐字节相同；改变未来数据会改变全量 hash，但历史成交/信号/快照不变，前缀最后的到期意图在追加根后可正常执行，这种变化不算历史成交变化。

## 未实现及风险

无策略、止盈止损/双触发、限价、收益面板/基准、持久化实验、Worker运行适配或UI入口；同步内核不承诺50,000根浏览器响应指标。输入仍受50,000根限制。Number来源精度损失无法追回，超出定点范围会阻断；流动性/市场冲击被简化。不能以2A通过宣称整个M2或用户Windows实机验收通过。无真实账户、API Key、钱包、真实资金或交易连接。

# Phase 6A · Windows 验证原型与验收报告

此候选面向 Windows 11 x64。它将研究工作台和十个生产 Worker 入口打入 Tauri 2，使用专用 WebView2 profile。前端工具链在构建机上使用 Node 24，运行桌面程序只需要兼容的 WebView2。工作台现有页面在专用 profile 里验证原功能，单独的 Rust IPC 验证 SQLite；完整业务存储适配及用户数据导入处于 6B 设计阶段。[架构决策及九库映射](phase-6a-architecture.md)

### 第二轮 Windows 实机复测

使用独立测试账户和本轮同一提交的验收包。记录 `build-info.json` 的源 SHA、Windows / WebView2 版本、显示缩放，以及包内 `SHA256SUMS.txt` 中两份 EXE 的实际校验结果。安装版与独立 EXE 分别登记。每项保留实测值、文件名、SHA-256 或错误原文，暂未执行的项目填 NOT TESTED。

## 可重现的技术验证

Windows 上通过安装后的同一 EXE 运行工作台。测试进程使用新的专用 profile；内置验收按真实页面、Worker、SQLite 和下载入口操作，将就绪、首个 Worker、完整结果或错误写成受限回执。外部驱动独立读取下载文件、比对 SHA，并从 Windows 采样进程树。系统 Edge 使用独立空配置和 Playwright 操作同一前端。正常交互启动不注册自动验收，不要求开启远程调试端口。

| 项目             | 如何判定                                                                                                                                                                                                                                                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发布输入         | PR 基线为联合包 `18aefef26884e5a8a10fd36e4e985365ff223e5f`。流水线检出 PR 的确切 head，从同一构建生成应用资源、松散 EXE 和每用户 NSIS 安装器。记录最终文件大小、SHA-256、签名状态及 Windows/运行时版本                                                                                                                                               |
| 页面、图表、中文 | 浏览器与安装后的应用应能打开首页和所有工作台页面。走实际 CSV 导入、保存、回放等入口，以真实 K 线像素和中文标签核实渲染。系统 Edge 自动归档截图；WebView2 字体、DPI 与下载交互的视觉效果由人工截图签收                                                                                                                                                |
| Worker           | 走生产模块 Worker 的消息、校验与合成计算，包括旧实验、固定子账户与共享池历史原件。专用验证页使用合成数据测试 CSV、研究、风险、归因、空会话保护等；回放的有效会话由独立 profile 中的工作台操作验证。桌面由页面按协调 Worker 的预算创建候选，记录串行 0 个、并行 2 个实际同源模块候选；浏览器保留协调 Worker 内的嵌套路径                              |
| 50,000 根对照    | 与原版 5E 相同的 MA 搜索、PCG32 种子 27、训练及测试各 25,000 根。100,000 根次求值，3 个候选，单通道与实际 2 路（申请 4 路）在 Windows 每个新 profile 中各运行一次，共三组。完整 result 的 canonical SHA-256、各窗口和排序均纳入比较；预期测试窗完成 2,082 笔交易。每次新生成的报告含独立 ID 和时间                                                   |
| IDB / SQLite     | 验证页创建随机命名的临时 IDB 并读回。原生自动化另在宿主新建的专用 profile 内，用原适配器核对九库十七个对象存储的名称、主键和版本；强制中止正文与摘要事务后两处均无测试行。Rust 命令没有路径或 SQL 参数，只操作新建的验证目录，提交 1 行、验证失败事务不增加行、SQLite Online Backup、重新打开恢复库并比较内容 SHA 和完整性。测试不会枚举旧浏览器配置 |
| 下载             | 从真实 Worker 导出合成报告。桌面按钮直接保存到系统下载目录，原生自动验收使用独立目录，重名时分配编号。两者均读回文件核对 SHA-256。系统 Edge 使用浏览器下载，外部驱动核对落盘长度和 SHA-256。跨端计算对照使用完整研究结果摘要                                                                                                                         |
| Windows 测量     | 加总应用进程树的私有字节与工作集，区分开始/空闲与 50,000 根负载峰值。记录启动至可交互的样本，标明系统缓存状态和采样方式。读磁盘获得安装器、独立 EXE、解包后安装目录及测试包大小。由同一版本的 runner 实测文件给出数字                                                                                                                                |

### 独立参照

Linux Chromium 154.0.8037.57 的全新临时配置在未改动的 5E 提交上取得完整 result 摘要 **`e3fb4410dc0bac12ca6dc1d108d4a6ae2f56107a47fc20bbda789469cbaf5d6b`**。该次旧版容量用例串行 4,759.5 ms、双 Worker 2,783 ms，报告文件 4,401,149 字节。6A 两端须重算同一摘要。Linux 上用 6A 的 Cargo.lock 运行两个 Rust SQLite 测试均通过。Windows 包体、WebView2 内存与启动计时只引用 Windows 实际运行的结果。

6A 本地 Linux Chromium 生产构建访问了 11 个页面和对应功能区，实际加载 10 类 Worker，能将 8 根合成行情的回放从第 1 根推进到第 2 根，保存后刷新仍从第 2 根继续。3 次新 profile 启动到工作台分别为 2,132、1,390、1,408 ms，到首个 CSV Worker 响应分别为 2,643、1,900、1,933 ms。首轮完整研究串行 3,865.5 ms、双 Worker 3,637.7 ms，下载文件 4,401,155 字节，经落盘校验。独立的 Linux 全量回归通过 668 项单元/集成、65 项端到端和 11 组 Python 参考。Windows 的原始结果另存为验收制品内的 `verification.json`，随同一运行的 `windows-results.md` 阅读。

## Windows 验收包与人工验收

从 Draft PR 的 **Phase 6A Windows prototype** 作业下载同一源 SHA、同一运行尝试的两个制品。**Windows x64** 包含应用 EXE、NSIS 安装器、`SHA256SUMS.txt` 及说明，**Windows evidence** 包含度量、功能断言和诊断。验收使用上传制品内层 ZIP 的 SHA-256，Actions 外层包装有另一 SHA。原型使用已安装的 Evergreen WebView2。缺失或版本低于前端基线的干净镜像需先准备微软官方对应架构运行时，离线机器使用 Evergreen Standalone Installer。记录测试发布者/签名和系统的实际提示。[微软运行时分发](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)

1. 在独立普通用户或干净虚拟机核对包 SHA，将 ZIP 解到含中文及空格的目录。记录 OS build、处理器、内存、WebView2 版本、电源模式和制品提交。分别直接双击应用、按用户安装后启动，记录启动到首页可操作的时间。
2. 使用内置合成样本，逐页打开研究工作台，从首页链接进入“桌面技术验证”，运行 50,000 根验证并保存 JSON。实际打开下载文件并与页面长度/摘要核对；点击 SQLite 验证查看提交、回滚和恢复结果。
3. 在无系统 Node 的 Windows 11 虚拟机复测直接启动；另在 WebView2 缺失、版本受组织策略限制的干净镜像记录结果。物理断网暂缓。CI 在已装 WebView2 的 Windows runner 上以仅含系统目录的 PATH 启动；“PATH 无 Node”和“系统从未安装 Node”的结果分别登记。禁止为测试卸载共享用户工作机的 WebView2。
4. 签收表记录 PASS / FAIL / BLOCKED / NOT TESTED，附实际包 SHA、每组结果、截图、首启与重复启动测量。真实 Win11 的中文字体、DPI、用户可见下载、物理断网、缺失 runtime 与登录策略由人工签收。审核停点为 6A Draft。

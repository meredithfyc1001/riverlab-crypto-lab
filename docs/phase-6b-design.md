## 所有者与调用路径

| 入口              | 负责的工作                                           | 持久化边界                                |
| ----------------- | ---------------------------------------------------- | ----------------------------------------- |
| React 工作台      | 选择输入、展示保存回执、错误、目录及备份位置         | 通过领域 Store 调用 Repository            |
| 浏览器 Repository | 原九个 v1 库、十七个对象存储，保留已有记录和事务语义 | 当前浏览器 profile 和 origin 的 IndexedDB |
| 桌面 Repository   | 序列化已校验的正文和列表摘要，协商协议版本，校验传输 | 本地 WebView 的 Tauri IPC                 |
| Rust 服务         | 服务实例、权限、版本、磁盘检查、SQLite 连接及事务    | 当前用户的固定应用数据目录                |
| 研究 Worker       | 原数值计算、校验、恢复、并发与取消                   | 桌面由工作台窗口代理数据操作              |

内置 HTTPS origin 随应用资源一起加载。应用进程在创建主窗口前初始化服务，按数据目录持有操作系统文件锁。应用关闭时结束服务，释放数据库连接和目录锁。异常结束后由操作系统释放句柄，下次启动由 SQLite 恢复已提交事务。服务生命周期随桌面应用，无网络监听器。主窗口只调用列入 capability 的具名命令。

## 桌面协议 v1

窗口协商主／次版本、schema、分块大小与读写能力，随后用 sessionId 和 requestId 关联数据操作。应用重启后重新握手。保存时先告知类型、原 ID、正文长度和摘要长度，按顺序每次发送至多 1 MiB 原始 UTF-8 字节。每块等待偏移回执，结束时校验总长及 SHA-256，再提交 SQLite。单条正文上限 256 MiB，摘要上限 20 MiB。取消可丢弃未提交传输；同一服务会话中提交回执丢失时按同一请求 ID 重试。读取同样按块核对长度与 SHA-256。协议摘要用于传输校验，原业务 Hash 保存在研究记录中。

风险、回放、市场状态及单币实验 Worker 可以通过一次性 MessagePort 请求来源记录。窗口只传递字节，Worker 解析后沿用原领域校验。高级研究和单币实验由 Worker 准备写入内容，窗口收到 SQLite 提交回执后显示保存结果。

## 存储与一致性

应用标识 `org.riverlab.crypto-lab.desktop` 决定每用户数据根，安装器和独立程序使用相同标识。正式数据根为 Tauri 的 appLocalDataDir 下的 `Research`，包含 `database/`、`logs/`、`backups/` 及服务锁。WebView 配置另存，CI 的 TestServices 只承载隔离样本。工作台可查询实际根路径、可用磁盘容量及写入检查结果。应用只为固定用途选取子路径；外部研究文件仍通过用户选择的文件入口处理。

桌面 v1 按业务类型和原 ID 标识记录。九类包含数据集、单币实验、策略规则修订、回放、风险研究、固定组合、共享资金池、市场状态及高级研究。正文和摘要在同一事务中添加或删除。规则库保持 100 个修订的容量限制。只有与原正文和摘要均相同的数据集重试允许幂等成功，其他重复记录或不一致的数据集返回冲突。

SQLite 的 application_id 为 `0x52564c42`，user_version 为 1。服务拒绝接管非空的未知库和更高的版本。每次连接启用外键、WAL、FULL 同步和 5 秒忙等待。每 1,000 个 WAL 页执行自动 checkpoint，正常关闭请求 TRUNCATE checkpoint。遇到活跃读者时保留旁文件供下次重开，从不手工清除 WAL。Rust Repository 的批次最多容纳 512 条、合计 512 MiB。批次中的任一写入出错时回滚整笔事务。工作台现有保存操作每次提交一个领域对象及其摘要。运行中通过 SQLite 在线备份取得一致快照；用户可以从工作台发起并查看成品位置。直接复制活动数据库主文件可能遗漏 WAL 中已提交的页。检查数据库时同时检查 SQLite 结构、外键及正文/摘要对应关系。使用 SQLite Online Backup API 生成临时快照，验证并同步后再用唯一文件名发布到 backups。

业务 schema、序列化内容、报告版本及 Hash 均由既有 TypeScript 领域代码解释。Rust 不计算策略或更改资金文本。回放继续验证原数据集 ID 和 Hash；自带来源快照的报告沿用现有独立复现流程。

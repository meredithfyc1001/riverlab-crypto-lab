# Phase 5D 实现复核

市场状态研究独立运行于已保存的单币种或组合实验。用户的模型定义、时间约束、统计口径和验收门槛在编码前完成评审。[技术设计](phase-5d-design.md)

## 时间与数值

分类器按顺序读取时间戳和收盘价，用长度为 N 的定点历史窗口计算标签；第 i 根权益变化读取第 i−1 根收盘标签。末根新标签保留在结果里。测试覆盖正负阈值等号、超过显示精度的极小越界、反复切换、前缀稳定性、未收盘、缺口和时轴错误。K 线背景、时长与区间盈亏都按归因期间排列。

含费成本按币种累计，部分卖出复用原统计的定点成本分摊。以相邻收盘市值之差减去成本变化得出浮盈变化，逐根核对其与已实现变化之和。各类贡献总和与原终值减初始本金严格相等。费用已计入权益。分布的每根简单收益先向零截断 12 位，均值与中位数按同精度表示，波动为总体标准差，用整数平方根向下取整。首根参考资产收益从首开盘到首收盘，后续采用相邻收盘；零权益分母从收益分布排除，贡献仍计入，少于两条收益时波动记 NA。

独立 Python Decimal 参考涵盖六条价格路径、缺口拒绝、一套含费跨状态单币账本及同一组合的两种人工指定参考。分别核验标签、区间、分布、暴露、费用和逐期间贡献。同一输入与确定的报告元数据生成相同的完整 SHA-256。创建新的研究记录会生成新 ID 与时间，因此完整报告身份也会改变。

## 报告库独立复核后的修正

独立复核在 `e580125` 复现了两个列表故障。5D 现在分别读取单币、固定组合和共享资金池的摘要；每份已提交的读取结果逐条校验。坏摘要旁的健康条目仍可选择。研究报告列表采用同一口径，显示可用摘要数与隔离数。打不开数据库或读事务中止时，页面保留该库的读取错误。正文在使用时仍执行原格式、版本、Hash 和内核重算校验。复现和修复试验仅写入隔离测试配置。[复现、数据对照和其他库检查](phase-5d-library-review.md)

## 兼容与恢复

原单币种报告内核、5C-A 固定组合验证器、5C-B 策略共享及再平衡验证器分别核对原始报告。5D 保存所有复现输入及原结果身份，通过重算还原大账本，避免在 JSON 中重复保存整份原实验的交易明细。重开和文件导入均校验独立报告格式、模型和归因版本、完整 Hash、源实验及研究重算结果。额外签名过的虚假结果也会被拒绝。保留原报告格式与旧 Hash 规则。

回归使用三份 RC 用户原实验、既有 5C-A 冻结报告，以及从 PR #13 实际合并提交导出的共享策略/再平衡合成报告。另以用户小包中的四份 5C-B 实际导出验证原结果，分别选两种参考资产完成八次研究复现。Chrome/Edge 实机旧报告、首测异常和补测数据见[实机基线](phase-5d-windows-baseline.md)。

## 浏览器边界与性能

## 验证与交付

安装锁定的 260 个 npm 包，全依赖和生产依赖审计均为 0 条公告。全部既有独立 Python 参考及 5D 参考通过。历史回归和新增的生产浏览器实验通过正常界面运行；依次验证显选参数、四类贡献守恒、图表、保存、真实下载、空配置重算和确认删除。首次全量命令在新增 E2E 文件的格式检查处退出；使用项目 Prettier 修正。开发 ZIP 连续运行四种源实验时，验包脚本曾读到前一份结果的 Hash；已在读取 Hash 前等待本次研究的标题，继续对照显示、导出及空配置恢复的完整身份。平台结果和 Windows 验收分别记录。[进度](../progress.md) · [实机验收单](phase-5d-acceptance.md)

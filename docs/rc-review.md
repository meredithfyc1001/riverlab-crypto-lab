# V1.0 RC 工程复核

## 历史兼容与恢复

三个 Windows 原始实验的文件 SHA-256 已与用户现场 ZIP 中的对应条目核对。旧包与 RC 都使用同一套配置与成交契约。回归从内嵌快照重算后逐项核对完整 payload，包含所有信号、订单、逐笔成交、费用、权益/回撤/基准曲线、统计和 runHash。旧的固定信号与回放使用各自原协议；历代可保存的回测实验均含正式策略。各版本的 Python 参考及冻结输出继续执行。[历史实验与权益对照](v1-rc-windows-baseline.md)

恢复入口在 Worker 校验文件和重算，再进入内存预览。数据库的两个 object store 在同一事务中使用 add，重复 ID 和并发确认都会保留原实验。专项测试覆盖放弃、刷新、损坏、原库缺失、同 ID 并发及再导出。复核中补上未来收盘及内嵌数据未知字段检查，并在预览显示累计手续费。[备份范围与限制](rc-backup.md)

## 审计、性能与页面

- 开发依赖的单条 minimatch 公告涉及 9 个包。兼容升级后全树及生产树均为 0。原始输出和逐包影响单独保存。[依赖审计](rc-dependency-audit.md)
- 50,000 根基线测量涉及报告 Hash、Worker 结果传输及全点曲线。保留原 20 秒和 1000ms 门槛，以重复实测评价变更。[性能复核](rc-performance.md)
- 工作台初次加载、数据中心两类样本、质量检查后明确保存、八页键盘与窄屏导航及缺失分块恢复均有专项检查。[界面实测](rc-ui.md)

## 本地包与验收记录

工作流把 PR head 用于三平台 checkout、Windows 打包和已解压 build-info 的复查。Windows 在中文空格路径解压后经正式 BAT 分别运行 Chrome/Edge。包测试包括从新浏览器配置恢复当前导出的实验和旧版 Windows V2 原件、重开后再导出、前台服务退出、端口释放。每项结果只归属于实际执行的平台、浏览器及提交。[当前候选 CI、制品及其有效期](https://github.com/meredithfyc1001/riverlab-crypto-lab/pull/11)

用户 2026-11-25 的实机记录属于基线 0.5.1-test。物理断网继续 NOT TESTED，RC 用户本地验收等用户执行后登记。恢复大型实验时解析、重算和 Worker 传输会使用额外内存；当前测试没有测定所有设备可承受的最大文件。混合旧版算法的文件须保留兼容版本本地包。回放依赖原数据 ID，新配置中恢复的数据集副本会使用新的 ID。[RC 用户验收清单](rc-acceptance.md)

# CSV 导入与质量口径（Phase 1A）

本轮提供 CSV 读取、字段映射、UTC 规范化和报告；不提供 ZIP 导入、行情图、指标、回测、保存/重开或实时数据。文件只在浏览器中处理，不上传。报告仅保留在当前数据中心页面会话，离开页面/刷新后清除，原文件不改写。

## 操作

1. 选择 UTF-8 CSV 或内置样本。内置历史样本无表头，其他样本有表头；用户文件自行确认表头设置和分隔符。
2. 选择逗号、分号或 Tab，检查原始预览和物理行号，逐项核对时间、开、高、低、收、量的映射。每个必需字段必须用独立列。额外列不参与 OHLCV 校验。
3. 时间单位可自动或明确指定 ms/us/带时区 ISO。填写预期固定周期（秒，可精确到 0.001 秒），或先检查后显式采用建议周期，再重新检查。
4. 阅读来源、SHA256、候选行、错误/警告和缺失区间。更改文件或检查约定会清除旧报告，不能把旧结果用于新配置。

## CSV 与资源边界

支持 UTF-8 BOM、LF/CRLF/CR、双引号字段、成对双引号转义和带引号的多行字段。严格拒绝未闭合引号、裸字段中的引号、结束引号后的杂项字符和列数不匹配；不猜测修复。错误明细保存原始记录片段（不含终止换行），保留引号、转义和记录内部换行，不以解析后的单元格重新拼接冒充原文。空白行计数并警告；逗号分隔的空单元格不是空白行。表头别名只对唯一匹配建议映射，重复列名要求手动选择。

浏览器文件上限 10 MiB；核心文本上限 10 Mi 字符；最多 50,000 数据记录、64 列、单字段 65,536 字符。触及上限明确阻断并要求拆分，不把截断结果称为完整。错误明细最多 1,000 条（错误/警告总数及各代码计数不截断）；界面每页 25 条，原始行内容最多 240 字符。候选预览前 20 行，原始预览前 5 行；缺口明细保留前 1,000 个、界面展示前 100 个，总缺口/缺失数量不截断。

解析、文件解码和哈希在独立 Worker，45 秒超时可中断；换文件、取消或离开页面终止旧任务，迟到结果不覆盖新来源。UI 不接收完整行情数组，避免主线程渲染大表。当前是有上限的内存解析，不宣称无限文件或流式存储支持。

## 时间与周期

- 内部统一 UTC 整毫秒，显示 UTC。自动识别使用固定 2009-01-01 至 2100-01-01 范围，逐一验证所有可识别整数时间是否一致为 ms 或 us；混用单位、秒级、范围外等不能可靠判定时要求确认。不依赖当前系统日期或本地时区。
- 明确指定后支持 1970-01-01 至 2100-01-01。微秒用 BigInt 解析，必须整除 1000，否则报错，不舍入。拒绝时间科学计数法、负数、浮点时间与溢出。
- ISO 必须为带 Z 或 ±HH:mm 的完整日期时间，最多三位小数秒；校验真实日历日期，拒绝无时区、非法闰日、24 点或闰秒。不默认本地时区。
- Binance Public Data 现货归档从 2025-01-01 起使用微秒；不能统一当毫秒。本轮真实样本是 2024 年毫秒记录，微秒样本为明确标注的人工合成数据，**不是已核验的原生 2025 归档**。
- 相邻最小正间隔仅作为周期建议，永远不自动确认。用户确认固定周期后，整数倍跳跃计缺失；非整数倍报错、提示周期/数据不一致，不能给出“无缺失”结论。仅支持固定时长，不支持日历月。

## 质量与完整性

OHLC 必须为正有限数，volume 必须非负有限数；拒绝空值、NaN/Infinity、十六进制和非零值下溢为零。OHLC 关系必须满足 low ≤ open/close ≤ high。价格为 Number 研究数据类型，不作金融账本金额计算，原始文本与文件哈希保留身份。

所有可解析时间检测重复（含首次行）及降序，即使该行价格另有错误也报告时间重复。不自动排序、去重或补价格。诊断可在时间副本上排序，但候选行情保持输入顺序。只有价格/量/时间可解析的记录参与内部区间诊断；错误行不能作为有效候选，完整性不能由候选行数证明。

报告分为需确认、存在错误、检查完成（仅文件内）。显示总行、有效候选、错误行、待解析行、错误/警告、来源与时间范围。全局映射/单位问题可能使部分行待解析，而非被判为有效。阻断结果不是已保存的数据集。

未指定期望起止区间，无法证明文件首尾完整；文件内没有缺口也不能证明市场完整性、停牌成因或来源真实性，始终明确提示。样本过少、坏行、非网格时间和未确认周期都不能静默宣称完整。

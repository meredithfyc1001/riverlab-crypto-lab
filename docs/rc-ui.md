# V1.0 RC 首次使用与页面加载复核

## 从空库开始

首次进入数据中心会先读取本地列表。列表确认为空后，入口置于备份管理前方。读库失败显示存储错误，不能据此判断用户没有数据。

1. 选择“真实历史样本 · BTCUSDT · 1 小时”（2024-10-28，24 根）、人工合成的毫秒或微秒样本，也可以选择自己的 CSV。点击样本只读取内置文件。
2. 核对来源、字段与时间。BTCUSDT 样本预期周期为 3,600 秒，合成样本为 60 秒。修改约定后重新生成质量报告。
3. 通过质量检查，填写交易对并确认警告后，选择“保存已检查数据集”。每次导入都会创建新数据集。原 CSV 由用户保管。
4. 保存成功后可直接进入回测中心，选择已保存的数据集、策略及成本，确认收盘后运行。刷新或关闭后，在同一浏览器配置和本机来源重开已保存记录。

行情空页可进入数据中心。策略研究、回测和历史回放的空库提示直接指向样本入口。风险分析需要正式回测实验，空库且缺少源实验时提供样本和实验文件恢复两个入口。清理网站数据、更换浏览器配置或更改本机端口都会影响访问本地记录，请分别导出所需的 JSON 备份。

## 首屏体积

在 Linux、Node.js 24.19.0、Vite 7.3.7 环境下，从合并提交 `e27a728` 独立构建基线，并用相同 Vite 生产构建方式测量 RC 开发快照。表中采用 Vite 的十进制 kB 和 gzip 估算。工作台首次打开只请求一个 JS 入口。

| 工作台首访资源       | 0.5.1-test | RC 开发快照 |
| -------------------- | ---------- | ----------- |
| JavaScript           | 570.71 kB  | 294.67 kB   |
| JavaScript gzip 估算 | 186.61 kB  | 94.90 kB    |
| CSS                  | 24.10 kB   | 24.84 kB    |

首屏 JS 减少约 48.4%。功能组件经现有模块入口按需载入，171.91 kB 的图表库留到需要它的页面。工作台状态继续保留在应用层，切页后仍可打开同一内存实验。各页共用的样式仍随首屏加载，避免首次从深链接进入时遗漏数据集管理区或实验区样式。每个分包均来自本机服务。

## 浏览器检查

Linux 系统 Chromium 154.0.8037.57 上，`tests/e2e/rc-first-use.spec.ts` 三项通过。

- 390 px 宽度分别以深、浅主题用键盘进入八个页面，逐页检查当前导航、功能区、空状态下一步和文档横向溢出。
- 从空库加载人工合成样本，质量检查和警告确认前不能保存；保存后按指引选择该数据集进行回测配置。关闭标签页并在同一浏览器配置重开，80 字中文交易对名称保留完整，加载历史样本预览后原记录仍然存在。
- 延迟页面 JS 请求时显示载入状态。缺少本机分包时显示错误提示，恢复文件后可从同一地址重新载入。

两份既有应用和导入集成测试共 8 项通过。专项调试首次运行使用了仅绑定 localhost 的临时预览而连接 IPv4，未能进入页面。将预览明确绑定 127.0.0.1 后，发现新增断言按整个 label 文本匹配会包含下拉选项；改为定位有明确可访问名称的组合框后，上述三项全部通过。完整平台、制品及用户实机记录见 [RC 验收记录](rc-acceptance.md)。

### 存储错误回归

中间提交的 Ubuntu Chromium 作业在原有配额用例失败。日志显示 5 秒内连续 14 次读到首条提示 `full`，预期为“空间不足”。空库中导入面板排到本地库之前，导入面板直接显示了浏览器原始异常，本地库才显示中文原因和备份操作。Linux 本地复测得到相同失败。[中间提交的失败日志](https://github.com/meredithfyc1001/riverlab-crypto-lab/actions/runs/45547503972/job/138980537375)

存储操作现在向两个入口传递同一条中文错误，并保留原始异常原因。独立构建后在 Linux Chromium 运行原有配额和存储拒绝用例，2/2 通过。确认写入失败后列表仍为空，内存数据可备份；原断言及 5 秒等待均保留。

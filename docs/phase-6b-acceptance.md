# Phase 6B Windows 验收清单

使用 Windows 11 x64 的新测试账户或可还原的虚拟机，安装 WebView2 Runtime。准备独立空目录及标明人工合成的 CSV。为每项记录系统、WebView2 版本、完整源提交、执行时间、实际观察与 PASS / FAIL / BLOCKED / NOT TESTED。以下人工检查初始均为 **NOT TESTED**。Phase 6A 第三轮另用其原清单登记。[6A 第三轮](phase-6a-verification.md)

| 项目             | 操作与通过依据                                                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 候选身份         | 对内层 ZIP、NSIS 安装器及独立 EXE 运行 `Get-FileHash -Algorithm SHA256`，对照同一提交的校验清单及 CI 摘要。                                                              |
| 首启、权限和空间 | 普通用户安装后打开工作台，选择“查看数据目录与服务状态”，核对实际用户目录、可用 GiB、服务／协议／schema 版本。记录目录与安装目录的关系。                                  |
| 数据与重开       | 用内置合成 CSV 创建数据集，保存研究并记录 ID、Hash 和完整导出文件。退出全部窗口，重新启动应用，核对数据集、报告、恢复结果和原文件摘要。                                  |
| 安装器与独立 EXE | 先关闭安装版，再从含中文与空格的路径启动独立版；同一账户应见同一记录。保持一个实例打开，尝试再启一次，确认第二次启动给出明确提示、原实例仍可读写。                       |
| 崩溃恢复         | 在这台一次性测试机保存一份合成记录，强制结束测试应用进程，重开后读回已提交记录，执行“检查数据库完整性”。中断写入的细粒度边界另查原生事务测试。                           |
| 手动备份         | 选择“创建数据库备份”，核对回执中的文件实际存在。继续添加一条合成数据后再备份，核对原备份仍然存在。                                                                       |
| 升级保留         | 保留测试账户数据，关闭应用，在同一安装位置覆盖安装同标识的候选版本。重开后核对原路径、ID、Hash、数据量和备份。若只有同版安装器，单独登记为覆盖安装，跨版本升级保持待测。 |
| 故障与只读行为   | 在隔离测试账户和测试卷上模拟数据根拒写或写满，核对错误与恢复重试、已提交记录和临时文件。原生 CI 的 ACL 和 SQLite 故障注入附独立证据。                                    |
| 浏览器回归       | 在新建的浏览器测试 profile 运行浏览器包，保存同一合成输入并重开，核对计算、Hash 和导出。比较桌面独立数据目录的记录数量。                                                 |

托管 CI 验收从 Draft PR 的同提交工作流取得。核对浏览器质量、三操作系统 Rust 测试及 Windows 安装后的运行证据。记录下载的是 GitHub 外层制品还是内层发行 ZIP，分别使用相应摘要。用户实机结果只登记实际执行的项目。

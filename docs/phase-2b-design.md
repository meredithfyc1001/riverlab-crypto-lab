# Phase 2B：策略与保护订单执行

本轮只交付纯 TypeScript 内核，沿用 [2A](phase-2a-design.md) 的数据阻断、18位账本、成本、数量过滤、无限流动性和可复现约定。无界面、收益面板、优化、AI、实盘或部署。2A文档是历史规格；以下为2B增量。

## 因果策略接口与参数

`createStrategy(config, intervalMs)` 每次运行创建独立状态，`onClose(candle)` 只接收一根已完成K线的冻结副本，不接收数据集、未来数组、索引查询函数或账户。引擎逐根收盘调用，信号只在下一开盘执行。接口无法认证外部调用方提供的时间顺序是否真实，但引擎验证全部数据及截止时间；内部要求严格连续、合法OHLCV、最多50,000根。保留固定测试信号入口，禁止同时提供策略和固定信号。

- MA：收盘SMA，fastPeriod默认10、slowPeriod默认30，均整数1..50,000且fast<slow；用18位整数滚动和交叉相乘精确比较均线。上一差值<=0且当前>0买，上一>=0且当前<0卖；首次两均线可用时仅建立基线，至少slow+1根才能交叉；相等不成交。
- RSI：period默认14，整数1..50,000；lower默认30、upper默认70，有限数且0<=lower<upper<=100。首N个价差均值初始化，再Wilder平滑；常量50、单涨100、单跌0。RSI<=lower买、>=upper卖，含等号；样本不足hold。RSI为Number指标标量，沿用1B的稳定均值及Wilder定义，不参与资金运算，不加隐藏epsilon；极接近阈值时受IEEE754舍入影响，版本与参数保留。独立高精度参考覆盖固定信号及0/50/100边界。
- 突破：lookback默认20，整数1..50,000；当前收盘严格高于此前N根high的最大值买，严格低于此前N根low的最小值卖；等号hold，当前根不进入比较窗口。使用18位整数和单调队列。

所有未知参数、缺少策略类型、NaN、非整数周期等明确拒绝。每根输出buy/sell/hold及原因，策略买卖数量为all。策略运行不加仓：已持仓buy、空仓sell分别记录拒单，原始信号保留；重新入场最早为下一根开盘。未完成样本不伪造信号，末根信号仍可到期。

## 保护价格、跳空与路径假设

`risk: {stopLossBps?, takeProfitBps?}`，各可省略表示关闭；启用值为整数1..9999，未知键拒绝，空对象等价全部关闭。相对于实际含滑点买入价（不含手续费）固定设置整仓保护：stop=floor(entry*(10000-stopBps)/10000)，take=ceil(entry*(10000+takeBps)/10000)。stop若小于1e-18则阻断整次运行，不悄悄改为0；止盈允许派生价格超过输入1e30边界。

启用保护时不允许向已有仓位加买；固定测试信号仍可部分卖出，剩余仓位维持原entry和保护价格。最后卖空后清除保护状态。每次新仓重新按实际成交价设置。

保护为触发式市价单，非限价承诺：触发参考价后仍按2A卖出滑点向下、名义额向下、手续费向上。可能低于止盈阈值，不以high/low裁剪滑点，也不保证交易所可成交。

1. 已有持仓先只读open：open<=stop以open触发止损；open>=take以open触发止盈。两者不可能同时为真。跳空止损不按更好的stop价成交；跳空止盈保守按take价成交，不领取超出阈值的开盘收益。时间为真实已知开盘时间。
2. 无开盘保护触发时，执行上一收盘的订单；开盘卖单自然优先于之后未知的根内路径。部分卖后余仓继续受保护；新开仓立即激活保护；若因买入滑点导致stop已高于或等于当前open，先在已知open立即触发退出，不能按更好的stop报价获利。
3. 根内low<=stop或high>=take包含触及等号。双触发采用stop先发生，明确`ambiguous-stop-first`，不按收涨/收跌编造OHLC路径。单触发按对应阈值作参考报价。
4. 开盘保护一旦尝试，待执行信号记录cancelled/risk-priority，即使保护因数量/最小名义额/滑点归零拒单，也不在同根重复执行或再尝试保护；持仓继续在下一根检查。根内保护每根最多尝试一次。
5. 新开仓后同根触及两者也使用保守stop先发生；买入之后的具体路径未知，允许一个开盘买入加一次保护卖出（激活即触发时发生于已知开盘，否则时间在根内未知）。不会在同根再买；当根收盘仍可产生下一根信号。

根内触发只能定位于[openTime,closeTime]，`timestampUtcMs`/订单生成与解决时间为null，携带区间和`phase: intrabar`；不伪造精确时间。开盘事件有精确UTC。保护事件没有策略signalCandleIndex（null），单独risk订单ID。每笔带entry/stop/take/触发类型/参考报价/假设；账本按根索引与open→intrabar阶段顺序审计，同根只允许开盘买入或部分卖出后保护清仓。

## 身份、审计和验收

算法版本升级；manifest加入规范策略类型/参数/版本、风险配置、执行假设，全部绑定runHash，实际策略信号绑定signalHash。改变全量未来数据会改变hash但既有信号/成交/快照不变。无时钟/网络/随机数；每次新建策略状态，相同输入JSON逐字节相同。

资金审计继续独立重算价格、数量、费用、现金/持仓、before/after与累计守恒，新增事件阶段/时间空值/唯一订单约束。审计不认证外部OHLC或保护触发真伪；触发正确性由内核及独立固定案例验证。

新增固定信号参考、独立Python高精度策略与Decimal成交参考、每个历史前缀、上涨/下跌/横盘、缺口/跳空/双触发、费用滑点/拒单/舍入、极端/空/不足/异常数据及篡改测试。保留全部159项旧测试和17项E2E，执行npm ci/check和三平台CI，超时/失败保留原始证据，不改默认阈值或删除断言。Windows用户验收单列，2B完成不签署整个M2。

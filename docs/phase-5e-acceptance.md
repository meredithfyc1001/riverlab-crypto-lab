# Phase 5D / 5E Windows 联合验收

在 Chrome 和 Edge 各建临时配置。准备 Node.js 24，下载 Phase 5E Draft PR 指定的最终内层 ZIP，核对 SHA-256 和 build-info.json 的完整提交、1.3.0-test.1、dirty=false。在含中文和空格的目录解压、双击 start-local.bat。两轮均使用同一份包，退出时检查 4173 端口已释放。5D 用户实机、5E 用户实机和物理断网的初始状态分别为 **NOT TESTED**。

先执行同目录的 [5D 完整清单](phase-5d-acceptance.md)，包括其报告库修复专项。下面的相对路径以解压目录下的 acceptance 为起点。

## 可直接导入的资料

- `fixtures/ma-2-4.json`、`rules-v1.json`、`rules-v2.json` 是既有实验，走实验中心。三个 `phase-5c-*.json` 分别走对应组合模式。核对重导 JSON 与原件的 SHA-256。
- `phase-5d-regime-synthetic.csv` 在 fixtures 内。导入为 60 秒人工合成行情，用突破周期 1，虚拟本金 1000.000000000000000003、费率 25 bps、买卖滑点 12 / 19 bps、数量精度 4、最小额 0、关闭保护，运行并保存单币实验。市场状态观察周期 1、阈值 1000 bps，期末总净盈亏为 654.897564292725。BULL、BEAR、SIDEWAYS、UNKNOWN 的贡献分别为 −8.420666436、979.894398232125、−316.5761675034、0。每根及连续区间详见 `fixtures/market-regime-reference.json`。
- 边界用 `fixtures/synthetic-single-50000.csv` 及 `synthetic-alpha-5000.csv`、`synthetic-beta-5000.csv`。均为 60 秒合成行情，导入时分别填不同交易对。用后两份做双资产组合。记录导入、运行、取消、导出和空配置恢复耗时及字节数。

## 5E 数值、筛选及用户操作

1. 在数据中心导入 `fixtures/phase-5e-rolling-synthetic.csv`，确认时间和 60 秒周期，填交易对、合成来源并保存。在策略中心导入 `fixtures/phase-5e-breakout-rule.json` 并显式保存。记录原始规则 ID、版本和 Hash。
2. 从策略中心进入高级研究，选择刚保存的具体版本及行情。用网格搜索买入突破周期 1 到 3、步长 1，卖出周期保持 2。本金 1000，手续费、买卖滑点、最小额及数量精度均为 0，关闭保护。不设筛选，按收益从高到低排序。滚动训练 24 根、测试 12 根（每次自动前移 12 根），状态周期 2、阈值 500 bps。运行前记录 3 个有效候选、2 折、最多 8 次子运行和 168 根求值。
3. 第一折训练选周期 1，训练 +12%，独立测试 −4.2%，终值 958、完成交易 2 次。第二折选周期 2，训练 +5.1%，独立测试 +9.6%，终值 1096、完成交易 1 次。对照各折 UTC 起止和训练散点、测试窗回撤及利润因子。打开市场状态表，用四类贡献加总核对选中窗口净盈亏。末尾浮盈按收盘估值，每折重新空仓起步。
4. 改成单次拆分。将最低交易数调高至超过观察交易数，核对每个被拒候选的原因及没有合格者时的测试状态。用多条件规则打开第二参数轴，试 MA 快周期大于等于慢周期、非法 RSI 阈值、过小步长和过多候选。核对拒绝原因与预算。以相同数据、参数和固定随机种子改变并发数，比较候选、排序、训练选择及测试结果。
5. 对较大候选集运行后取消，马上启动另一组已知参数。核对进度属于当前任务，已取消任务不能保存完整报告。分别在结果列表中选中参数、显式另存新版本，返回策略中心核对原版与新增版的内容。在 Phase 3 入口复测旧报告。
6. 保存完整报告，导出 JSON 和 CSV。刷新重开后重导。新建空配置，仅选该 JSON，待重算、核对报告 Hash 后确认保存。再次刷新并重开，比较完整文件。重复保存同 ID、未知版本、篡改结果、损坏 UTF-8 及超过 32 MiB 的文件分别应给出错误。原报告仍可重开。
7. 数值期望另存于 `fixtures/advanced-research-reference.json`。已装 Python 3 的机器可在 acceptance 目录运行以下两个只读核验命令。直接核对 JSON 期望可在无 Python 的 Windows 配置进行。

```powershell
python reference/advanced_research_reference.py --check
python reference/market_regime_reference.py --check
```

## 四库故障隔离

只在准备丢弃的浏览器配置操作。分别创建至少两份数据集、两个规则版本、两份已存风险报告及两份回放。保留回放指向的原数据集。各选一份健康记录先重开并导出，保存其 JSON 作为对照。

1. 找到包内 acceptance-library-fixture.js。在本机应用的 DevTools → Sources → Snippets 新建片段，复制文件内容并运行。Console 输入 `await riverlabAcceptanceFixtures('5E')`，记录输出的来源及夹具主键。它给四个库各新增一条坏记录，并给数据集、风险、回放库新增可选中的坏正文副本。刷新对应入口，记录各库可用数、隔离数及实际报错。相同夹具可重复执行。
2. 重开同库另一份健康记录，走原有校验、复现与导出入口。比较导出内容和 Hash。在一个库仍有坏记录时使用其他库。复查被隔离记录在原主键保留。再选择名为“联合验收 · 正文损坏”的副本，打开时应显示原验证错误。

## 分工及交付顺序

1. 存储层复用 5D 的逐条摘要校验及库级错误诊断。风险、回放、行情和规则库分别返回健康记录、隔离数及事务错误，正文按原契约验证。测试保留损坏的 IndexedDB 原件，比较健康条目的重开和导出。
2. 独立优化内核从具体规则版本的已验证副本生成参数轴。仅允许编辑该条件已有的数字字段。组合须通过 5B 规则校验，搜索空间在计算第一笔收益前确定。网格遍历有界组合，随机搜索以固定种子无放回抽样，重叠候选按规范参数去重。预检返回生成量、无效数、可运行数、窗口、子运行数和总根次。
3. 按序指定收益、回撤、利润因子、已完成交易数的筛选和排序。收益、利润因子和交易数方向为高者优先，回撤方向为低者优先。不可用指标显式标记；确定性参数序号打破同分。保留每个候选的参数、统计、执行错误及筛选原因。
4. 每折只按当前训练窗口筛选、排序，锁定参数后只运行该候选的测试窗。每个窗口分别初始化现金和指标，空仓，无跨界信号；包含末根未平仓头寸的真实估值。滚动测试窗互不重叠，末尾不足一窗时记录未用根数。展示逐折训练与样本外差异及过拟合提示。样本外结果和市场状态均不参与选择。
5. 复用原成交引擎、固定精度统计及 5D 连续账本归因。选定候选的状态表列出四类贡献，核对状态之和与该窗口净盈亏。上一根收盘标签仅用于下一根。单个窗口有独立本金，不合成跨窗收益或资金曲线。
6. Worker 池限制并发、快照复制及同时求值的根数。同一折的训练结果按确定性次序收集，候选级错误可追溯；通讯或任务级错误使整次任务失败。取消终止关联 Worker 并清除旧任务响应。只有完整成功的结果才允许保存。
7. 版本化报告和独立 IndexedDB 库包含来源快照、精确规则版本、全部研究设置、计划、各折训练、锁定、测试、算法版本和 Hash。文件读取先查体积，恢复时在 Worker 验证原始字段、重算结果和 Hash，同 ID 新增拒绝覆盖。CSV 为人读摘要，JSON 支持空配置恢复。策略另存需用户显式选中候选并确认。
8. 独立 Python 参考使用合成平 OHLC、整数手和零成本，检验训练排名反转、下一根执行、按窗收益与回撤。保留原十组参考和 629 / 60 回归。在原始上限和扩容目标分别测量瓶颈，完整证据达到容量门槛后再调整准入。
9. 三个平台运行完整检查。Windows 验包作业从同一 clean head 生成 ZIP，在中文空格目录以 Chrome 和 Edge 验证旧流程、优化流程与各库故障隔离。包内提供可直接选择的样本、独立参考和两份用户验收单。

Phase 3 的描述性比较入口、算法及旧报告验证路径继续独立。研究在本地历史数据上进行，范围限于虚拟现货账户。

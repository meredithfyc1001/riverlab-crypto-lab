# RiverLab Crypto Lab Phase 6C-A · Windows 浏览器测试包

仅供学习研究。所有交易、费用和权益均为本地模拟结果。历史表现不代表未来表现，本工具不提供投资建议。

双击 `start-snapshot.bat` 可在原本机 origin 直接打开完整快照导出页。此入口只加载导出页面，不打开工作台。读取旧历史请选原浏览器、原 profile 和原端口。本轮验收请用单独测试 profile 和合成样本。Windows 浏览器包需要系统安装 Node.js 24，独立校验器使用 Python 3。[6C-A 验收](acceptance/phase-6c-a-acceptance.md) · [格式与九库映射](acceptance/phase-6c-a-snapshot.md)

常规工作台仍由 `start-local.bat` 打开，既有研究和样本保留。[5D 清单](acceptance/phase-5d-acceptance.md) · [5E 清单](acceptance/phase-5e-acceptance.md)

## 核对测试包并启动

1. 使用有仓库访问权的 GitHub 账号，打开 Phase 6C-A Draft PR 最终提交对应的 Project quality 运行。Windows local test ZIP 作业摘要提供下载链接、完整提交 SHA、内层 ZIP 和 Actions 外层制品各自的 SHA-256。制品自上传起保留 14 天，过期时间以 GitHub 制品记录为准。
2. 下载并解开 Actions 外层 ZIP。用 PowerShell 对内层 ZIP 执行 `Get-FileHash .\RiverLab-Crypto-Lab-Local-Test.zip -Algorithm SHA256`，与同名 `.sha256` 文件及作业摘要比对。在含中文和空格的目录“全部解压”内层 ZIP。
3. 在内层解压目录确认 `build-info.json` 中 `version=1.3.0-test.1`、`phase=Phase 6C-A`、`dirty=false` 及完整提交 SHA 与 PR 最终提交一致。使用以下 PowerShell 命令检查包内文件。

```powershell
Get-Content -Encoding utf8 .\SHA256SUMS.txt | ForEach-Object {
  $expected, $file = $_ -split '  ', 2
  if ((Get-FileHash -LiteralPath $file -Algorithm SHA256 -ErrorAction Stop).Hash.ToLowerInvariant() -ne $expected) {
    throw "SHA-256 mismatch: $file"
  }
}
```

4. 系统需预装 Node.js **24 LTS**。双击正式 `start-local.bat`，保持窗口打开。出现 `READY` 后使用 Chrome 或 Edge 访问窗口显示的 `http://127.0.0.1:4173`。启动器会请求打开系统默认浏览器。下载包和安装运行时需要网络，日常使用由回环 HTTP 提供静态资源。
5. 按浏览器分别记录版本、开始与结束时间、实测项目及错误。物理断网由用户暂缓，状态为 **NOT TESTED**。CI 在 Windows 上运行 BAT 并限制外部请求，结果单列。

## 样本、数据与回测

- 在新浏览器配置打开数据中心，分别尝试“真实历史样本 · BTCUSDT · 1 小时”和人工合成样本入口。加载后检查名称、来源、时间单位与质量报告，主动保存前应保持原有数据集列表。
- 真实内置样本为 2024-10-28 BTCUSDT 现货 1 小时、24 根 K 线，周期填写 3600 秒。CSV 使用 UTF-8，最多 10 MiB、50,000 根。核对映射、UTC 时刻、重复、缺口、OHLCV、交易对及警告，随后点击“保存已检查数据集”。人工合成样本仅用于演示和测试。
- 在行情页核对 K 线与指标。在回测中心选择已保存样本，使用 MA 快 2 慢 4、虚拟本金 1000 USDT、双边手续费及买卖滑点各 10 bps、关闭止盈止损，确认全部 K 线已收盘后运行。核对 3 笔成交、25 个曲线点、最终权益 1021.9223539166904185 USDT。默认 MA 慢线 30 在此样本中尚未预热完成。
- 查看成交账本、费用、逐点权益和回撤，保存实验，并分别导出实验 JSON 与成交 CSV。关闭并重开同一浏览器配置、同一地址，主动打开实验并复现。浏览器存储会因清理、隐私模式或配额失效，重要研究须保留 JSON 文件。

## 在新的浏览器配置中恢复回测实验

1. 在策略中心创建一版规则，在回测中心用该版本完成一次回测，并导出实验 JSON。记录实验的版本、名称、runHash、成交与权益。
2. 在独立的新浏览器配置访问相同地址。打开“实验中心”，使用“导入回测实验 JSON”选择原文件（最多 256 MiB）。Worker 校验格式与版本，按嵌入的行情、策略和成本重算，并核对 Hash 与结果。原浏览器中的数据集和策略版本可以留在原处。
3. 核对恢复预览，确认已保存列表尚无该实验。尝试放弃预览或刷新，再次导入后点击“确认保存导入的实验”。刷新并打开保存的实验，导出 JSON，对照完整记录。点击“复现本实验”后对照新运行的逐笔成交、逐点权益、统计和 runHash。
4. 重复导入同一标识的文件应被拒绝覆盖。使用单独的测试副本更改版本、破坏 JSON 或修改成交数值，逐一确认拒绝提示，再打开先前保存的实验核对结果。

## 固定子账户组合回测

1. 在数据中心保存两个不同交易对的数据集。使用同一报价货币、相同固定周期、存在共同历史区间的已收盘 K 线，交易对可填写 `BTC/USDT`、`ETH/USDT`。人工生成的数据应在来源说明中注明。组合内所有原始数据合计最多 10,000 根，截去的部分也计入。
2. 打开“组合回测”，选择数据集并为各子账户配置内置策略或已保存的规则版本。输入总虚拟本金与初始分配比例，例如 1,000 USDT 及 60% / 40%。检查双侧滑点、手续费、数量精度及保护参数。先试 60% / 41%，确认权重错误阻止运行，再恢复正确比例。
3. 核对 UTC 毫秒共同区间和每个数据集截去的范围，明确确认后运行。核对子账户本金之和、组合收盘总权益与各子账户权益之和。检查配置权重、当前权益占比、持仓市值占比，各条曲线、盈亏与费用、独立成交、相关性及组合买入持有基准。
4. 保存组合，记录组合 Hash，导出组合 JSON 与汇总 CSV。刷新后打开保存的组合并完整复现。使用独立浏览器配置打开组合页，导入 JSON，查看重算结果后保存。刷新、重开、再次导出并核对组合 Hash、策略快照、资金、成交和曲线。组合 JSON 最大 32 MiB。
5. 修改测试文件副本的版本、Hash 或成交，分别检查拒绝提示及已存列表。删除一个专门创建的测试组合，刷新核对列表，并确认旧单资产实验仍可打开。记录首次大报告导入到恢复预览的实际耗时以及错误提示标点。

## 共享资金池与定期再平衡

1. 从回测中心进入组合回测，在同一浏览器分别运行两个新模式。沿用两份同报价、同 UTC 周期的独立行情，再以五个资产复测。设置相同初始本金，记录确认的共同开收盘区间。
2. 在“策略驱动共享资金池”中分别选择内置策略与一版已保存的规则，设置每币种的费用、滑点、保护和目标预算，例如 50% 和 40%。核对预留现金比例 10%。交换资产排列，再比较同一开盘申请和批准的预算、费用、实际成交数量及现金。将最小成交额调高，核对未成交原因和保留现金。
3. 切换为“定期目标权重再平衡”，输入例如 50%、40% 与现金 10%，设置每 2 根已完成 K 线调仓。查看首次收盘决定之后的开盘成交，以及涨跌后的减仓、增仓、调仓前后实际权重、目标权重与剩余偏差。调整现金到 11% 验证总和错误，再改回 10% 并重新确认。
4. 核对买卖前后共享现金和对应币种数量、收盘总权益与逐币市值之和、满期净盈亏与各资产贡献之和。对照买入持有基准、完整净值曲线和最大回撤。记录手续费和精度造成的偏差。在运行边界样本时尝试取消，确认可开始新运行。
5. 两种模式各保存一次，分别导出 JSON、明细 CSV。刷新并重开，使用空白浏览器配置在对应模式导入 JSON、完整复现、显式保存，再次刷新导出，核对模式、策略版本、事件、成交、权重、统计和 Hash。另以历史固定子账户、MA 2/4、规则 V1 与 V2 的原件核对兼容。物理断网继续记录 **NOT TESTED**。

## 其他备份文件

| 文件                | 恢复入口与依赖                                                                                                                                                  |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据集 JSON         | 数据中心，最多 20 MiB / 50,000 根。含规范化行情、来源、解析与质量摘要。建议同时保留原始 CSV。                                                                   |
| 不可变规则版本 JSON | 策略中心，最多 128 KiB。校验后作为内存草稿，显式保存才进入版本库。同家族同版本不能覆盖。                                                                        |
| 策略研究 JSON       | 策略中心，最多 25 MiB。含完整行情与研究参数，在 Worker 重算。研究结果只保存在内存，刷新前导出。                                                                 |
| 历史回放 JSON       | 历史回放，最多 10 MiB。包含已执行的动作、日记、游标与行情身份。依赖原存储中的同 ID、同内容数据集。数据集 JSON 恢复会分配新 ID，无法用新副本在另一配置重开回放。 |
| 风险报告 JSON       | 风险中心，最多 25 MiB。内嵌源实验复现输入、抽样模型及种子，重算后可显式保存。                                                                                   |
| 比较、成交等 CSV    | 供阅读和逐行核对。恢复实验、回放或研究时应选择相应类型的 JSON。                                                                                                 |

## 原有功能与退出

- 在策略中心保存两版命名规则，重开旧版本，导出并比较旧记录。规则每侧最多 5 条条件，修改保存产生新版本。规则策略可运行回测，当前样本内外和网格研究支持 MA、RSI、突破。
- 在策略研究中确认收盘、成本和过拟合警告，运行固定候选或有限网格，导出并重开研究 JSON。各窗口独立预热、重置资金，滚动测试窗口不重叠。
- 在历史回放中前进一步、排队虚拟买入、验证下一根开盘成交、添加日记、保存并重开检查点，再导出 JSON/CSV。保留所选数据集备份。
- 在风险中心选择至少 20 根且净权益有变化的正式实验，以相同种子和配置重算，核对分位和模型内频率，保存、刷新重开、导出 JSON/CSV。抽样分布不能预测未来，亦不代表真实亏损概率。
- 检查原有八个页面及组合回测入口的导航、深浅主题和窄屏显示。仅用键盘完成导航、选择文件、预览及确认。页面内资金为 18 位定点，采用简化的滑点和流动性假设。
- 在服务窗口按 **Enter**（或 q 再 Enter、Ctrl+C），检查 `STOPPED`、前台窗口退出及 4173 端口释放。使用同一地址重开应能读回已保存的记录。

## 启动与本地存储故障

- 找不到 Node 或版本错误时，安装系统 Node 24 LTS 后重试。
- 端口被占用时，关闭上一个 RiverLab 窗口。也可运行 `node server.mjs --port=4174`，新端口使用独立浏览器存储。返回原端口可以查看以前的记录。
- 缺少资源时完整解压内层 ZIP，保留 dist、server.mjs 和 BAT 的相对位置。须通过本机 HTTP 访问。
- 浏览器未自动打开时，手动打开启动窗口中的回环 URL。浏览器配额不足或组织策略限制写入时，保留当前页面并导出 JSON，以便在允许存储的配置中恢复。

## 市场状态研究

1. 在“市场状态研究”选择一个已保存的单币实验，填写观察周期与趋势阈值，运行归因。按上一根收盘已知状态核对下一期间的权益变化。首段计入 UNKNOWN，四类净盈亏贡献之和应等于原实验最终权益减去初始本金。
2. 分别选择固定子账户、共享资金池、定期再平衡实验，显式选择参考资产后运行。查看共同时间轴、区间 UTC 边界、成交、费用、暴露和图例，记录参数及报告 Hash。
3. 保存并导出 JSON 与 CSV，刷新重开。在第二个空白浏览器配置只导入市场状态 JSON，显式保存、刷新重开并核对完整报告、Hash 及汇总。使用专用测试报告检查删除确认。在窄屏下分别查看深浅主题。
